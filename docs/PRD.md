# Media Manager - 产品需求文档 (PRD)

## 产品愿景

打造一个精美实用的跨端媒体管理器，支持 Android、iOS、未来扩展桌面端。用户可以浏览本地、云端、已上传的图片和视频，进行搜索筛选、编辑、分享，体验流畅自然。

## Sprint 1 目标

把现有"能用的 demo"提升为"精美的可用产品"。

## Sprint 1 功能清单（按优先级）

### P0: UI/UX 精美化 + 动画体验
**用户故事**: 作为用户，我希望 App 启动到浏览图片的整个过程流畅自然，动画过渡丝滑，视觉风格统一精致。
**验收标准**:
- Material3 动态色调适配
- 页面切换动画（Tab 切换、预览进入/退出过渡）
- 网格项加载渐入动画
- 沉浸式状态栏 + 导航栏适配
- 暗色/亮色主题完善
- 启动屏（Splash Screen）

### P0: 搜索和筛选
**用户故事**: 作为用户，我可以按关键词搜索、按类型/日期筛选媒体，快速找到目标图片。
**验收标准**:
- 顶部搜索栏（可展开/收起）
- 按文件名关键词搜索
- 按类型筛选（图片/视频）
- 按日期范围筛选
- 搜索结果高亮

### P0: 视频支持
**用户故事**: 作为用户，我可以浏览和播放视频文件，不仅有图片。
**验收标准**:
- 后端支持视频缩略图生成（ffmpeg 抽帧）
- 前端网格中视频项有播放标识 + 时长
- 点击视频项进入全屏播放器
- 播放器支持播放/暂停/进度条/全屏
- 网盘视频列表加载

### P1: 设置页
**用户故事**: 作为用户，我可以配置后端地址、切换主题、查看版本信息。
**验收标准**:
- 设置入口（TopAppBar 齿轮图标）
- 后端地址配置（输入框 + 保存 + 连通性测试）
- 主题切换（跟随系统/浅色/暗色）
- 关于页（版本号、项目地址）
- 设置持久化（DataStore/SharedPreferences）

### P1: 按时间分组展示
**用户故事**: 作为用户，我看到的媒体按日期分组展示，有"今天/昨天/具体日期"的 section header。
**验收标准**:
- 网格按日期分组，每组有 sticky header
- header 显示"今天/昨天/YYYY-MM-DD"
- 分组内仍是网格布局
- 滚动时 header 悬停

### P1: 图片详情页
**用户故事**: 作为用户，我点击图片可以看到详细信息（EXIF、大小、日期、分辨率）。
**验收标准**:
- 全屏预览底部可展开详情面板
- 显示文件名、大小、分辨率、拍摄日期
- 显示 EXIF 信息（如果有）
- 显示文件路径/来源

### P2: 批量操作增强
**用户故事**: 作为用户，我可以全选、批量上传到云端、批量分享。
**验收标准**:
- 长按进入选择模式
- 全选/反选按钮
- 批量上传到已上传区
- 选择计数器动画

### P2: iOS 端完善
**用户故事**: 作为 iOS 用户，我有和 Android 一致的体验。
**验收标准**:
- iOS 端构建通过
- 相册权限申请流程正确
- 缩略图加载性能达标
- 基本交互一致

## 跨端要求

- Kotlin Multiplatform 共享业务逻辑
- Android: Material3 + Compose
- iOS: Compose Multiplatform + 原生桥接
- 未来: 桌面端 (macOS/Windows) 复用 commonMain 代码
- 后端: Go + gRPC + REST，跨平台服务

## 技术约束

- 后端: Go 1.21+, gRPC, REST gateway
- 前端: KMP + Compose Multiplatform
- 构建: Gradle (KMP), Go build
- 编码 agent: Claude (复杂), Codex (执行)

# Sprint 2

## Sprint 2 目标

把产品从"功能完整"提升到"精美好用"。Sprint 1 完成了浏览态(美化/UI/视频/搜索/分组/详情),Sprint 2 聚焦**管理态与组织态**:让用户能对媒体做动作(收藏/分享/批量/归入相册),并补齐此前遗留的两个结构性技术债——后端无持久化层、前端单文件臃肿且无磁盘缓存。这两个地基不夯实,后续所有"组织"功能都是无源之水。

## 选型说明(为什么不选某些方向)

- **图片编辑(裁剪/旋转/滤镜)**:工程量大,需引入图像处理库(media3/AVFoundation 帧提取或自研),且独立于"组织"主线,留到 Sprint 3。
- **iOS 端完善 / macOS 桌面端**:平台铺面性工作,与核心价值链正交,本轮不在主线(桌面 target 已保留但未启用,作为 Sprint 3 候选)。
- **深色模式完善**:动态色调+三主题已在 Sprint 1 落地基本可用,边际收益低。
- **动画细节打磨**:在各项功能任务的验收标准里内嵌,不单列任务。
- **错误处理/边缘情况**:抽测在后端持久化任务里以单测形式打底,并在各功能任务验收中要求"空态/失败态/网络中断"三态处理。

## 技术债先还(Layer 0,本 Sprint 必做)

这两项是后续功能的地基,排在所有功能任务之前并行执行:

1. **后端持久化层**:当前元数据每次请求 `os.ReadDir`+`os.Stat` 实时推导,关进程即丢,无法承载收藏/相册等用户态。引入 index.json(轻量)或 SQLite(可演进),并填充 `MediaMetadata` 预留的 exif/width/height 字段,删除时级联清理缩略图孤儿。
2. **前端主页面拆分 + 磁盘缓存**:`MediaListScreen.kt` 单文件 1256 行承载全部功能,多功能并行修改必冲突;`BackendImageLoader` 仅内存缓存无磁盘层,离线/反复滚动体验差。拆分组件、把 `SelectionBottomBar` 改为**可配置动作槽位**(后续功能只注册 action 不改组件),并启用 Coil 3(已在 version catalog 待命)补磁盘缓存。

## Sprint 2 功能清单(按优先级)

### P0: 后端持久化层(技术债地基)
**用户故事**: 作为系统,媒体元数据与用户态(收藏/相册成员)在进程重启后依然存在,缩略图不无限堆积。
**验收标准**:
- 引入持久化: index.json(轻量起步)或 SQLite,落盘 uploads 元数据 + 用户态
- 上传/删除时正确读写持久化;`created_at`/`updated_at` 不再仅靠 ModTime
- 填充 `MediaMetadata` 的 width/height(图片解码尺寸、视频 ffprobe),exif 尽力提取(可选)
- 删除媒体时级联清理 `thumbnails/` 中对应缓存,消除孤儿
- 缩略图缓存加入上限淘汰(LRU 或按总容量阈值)
- 补 service 层关键路径单测(列表/上传/删除/缩略图命中与缺失至少各一)
- `go build ./...` 通过,`go vet ./...` 无新增告警

### P0: 前端主页面拆分 + 磁盘缓存(技术债地基)
**用户故事**: 作为开发者,主页面拆成可独立修改的组件;作为用户,网盘/已上传图片二次滚动不重新下载、弱网下有缓存可用。
**验收标准**:
- `MediaListScreen.kt` 拆分: 抽出 MediaGridItem / SelectionBottomBar(可配置动作槽位)/ ImagePreviewDialog / EmptyErrorState 等独立组件,单文件行数显著下降,各组件可被多层功能复用
- `SelectionBottomBar` 支持"注册 action"模式: 接收 `List<SelectionAction>` 而非硬编码上传/删除,动作按钮文本/图标/回调由调用方注入
- 启用 Coil 3(composeApp commonMain 依赖取消注释),迁移 `BackendImageLoader.loadThumbnail`/`loadFullImage` 调用点,获得磁盘缓存+生命周期管理;保留原有内存缓存语义不回归
- 网盘图片 Tab 滚动复访不再重新请求缩略图(磁盘命中)
- 顺手修复 Sprint 1 遗留的时区 P0: `MediaViewModel.localTimeZoneOffsetMillis` 当前硬编码 `0L`,导致按 UTC 划分日期分组,UTC+8 晚间错位(深夜照片划到"昨天");改为读取真实系统时区偏移(expect/actual,kotlinx-datetime 或平台原生),`DetailPanel` 时间显示同步用本地时区
- `bash gradlew :composeApp:assembleDebug` 通过

### P1: 批量操作增强
**用户故事**: 作为用户,我可以全选/反选,批量上传到云端、批量分享、批量移入相册,操作有进度反馈。
**验收标准**:
- 选择模式补 全选/反选 按钮,选择计数动画完善
- `SelectionBottomBar` 扩展为动作槽位后,新增"批量分享""批量上传到云端(已上传区)""批量加入相册"动作(部分动作依赖其他任务,先占位注册)
- 批量上传/删除有进度条或计数进度反馈,失败项单独提示可重试
- 网盘图片 Tab 可进入选择模式(放宽 `selectedTab != 2` 限制,提供合理的可执行动作)
- 空态/失败态/网络中断三态处理

### P1: 收藏
**用户故事**: 作为用户,我可以给媒体加星收藏,在收藏视图快速回看。
**验收标准**:
- 后端: 持久化用户收藏态;新增收藏端点(加星/取消/查收藏列表)或复用 list 的过滤参数 `favorite=true`
- 前端: 媒体项收藏角标(长按或预览面板内 toggle),收藏状态持久化
- 收藏视图入口(可在现有 Tab/筛选条中提供"收藏"筛选项)
- 离线: 已缓存的收藏列表弱网可展示
- 空态/失败态处理;`MediaViewModel` 收藏状态与列表联动正确

### P2: 分享
**用户故事**: 作为用户,我可以把媒体分享到系统分享面板(微信/相册保存/AirDrop 等),单张或批量。
**验收标准**:
- expect/actual 平台分享: Android 走 Intent.ACTION_SEND / FileProvider,iOS 走 UIActivityViewController
- 单张分享(预览面板+网格项长按菜单)与批量分享(`SelectionBottomBar` 动作)
- 分享原图二进制(优先复用磁盘缓存命中,避免二次下载)
- 分享文件不存在/未缓存时降级提示,不崩溃
- 跨平台行为一致(Android 与 iOS 均能拉起系统分享)

### P2: 相册管理
**用户故事**: 作为用户,我可以创建自定义相册、把媒体移入/移出相册、按相册浏览。
**验收标准**:
- 后端: 持久化相册实体(name/cover/成员 media_id 列表);端点 增删查/成员增删
- 前端: 相册管理入口(设置页或新 Tab/抽屉),创建/重命名/删除相册
- 单张与批量"加入相册""移出相册"动作(复用 `SelectionBottomBar` 槽位)
- 相册视图: 封面网格,点入看相册内媒体
- 删除媒体时从所属相册级联移除成员(不留悬空引用)
- 空态/失败态处理
